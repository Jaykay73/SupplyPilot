# SupplyPilot — Database Schema & Data Dictionary

## 1. Schema Overview

SupplyPilot utilizes a normalized relational schema representing a pharmaceutical manufacturing operation (*PharmaPulse Synthetics*). All tables are defined using SQLAlchemy 2.0 with strict typed constraints, foreign keys, and indexed query paths.

```
                           ┌─────────────────┐
                           │    Customers    │
                           └────────┬────────┘
                                    │ 1
                                    │ N
                           ┌────────┴────────┐
                           │     Orders      │
                           └────────┬────────┘
                                    │ 1
                                    │ N
                           ┌────────┴────────┐
                           │   Order Items   │
                           └────────┬────────┘
                                    │ N
                                    │ 1
                           ┌────────┴────────┐       1 : N       ┌────────────────────┐

                           └────────┬────────┘      (BOM)        │       (BOM)        │
                                    │ 1                          └─────────┬──────────┘
```

## 2. Table Catalog

### Core Catalogue
- `products`: Finished pharmaceutical formulations (e.g. `PRD-001` Paracetamol IV Solution, `PRD-002` Amoxicillin-Clavulanate). Contains unit sales price, standard batch size, safety stock thresholds, and production lead hours.
- `raw_materials`: Active Pharmaceutical Ingredients (`API-004`), excipients, solvents, and primary packaging components (vials, elastomeric stoppers, flip-off seals).
- `product_materials`: Bill of Materials (BOM) linking products to raw materials with required unit ratios.

### Commercial & Operations
- `customers`: Healthcare authorities, university clinics, and distributor partners.
- `orders`: Purchase orders with requested delivery dates, status, risk indicators, and monetary totals.
- `order_items`: Line items specifying product, quantity, unit price, and fulfilled count.
- `inventory`: Physical inventory tracking `on_hand`, `reserved`, and `incoming` quantities. Deterministic availability is computed as:
  $$\text{available} = \max(0, \text{on\_hand} - \text{reserved})$$
- `inventory_reservations`: Atomic allocation of stock to specific customer orders or production batches.

### Supplier & Procurement
- `suppliers`: Qualified pharmaceutical suppliers with lead times, reliability scores (0.80–0.98), and status.
- `supplier_materials`: Supplier-material qualification matrix including contract pricing, minimum order quantities (MOQ), and approval flags.
- `supplier_delays`: Formal delay event notifications triggering downstream operational cascades.

### Production
- `production_lines`: Dedicated cleanroom and packaging lines (Sterile Injectables, High-Speed Tableting).
- `production_batches`: Scheduled production runs with target quantities, line allocations, and block status.
- `production_schedule`: Time-slot allocation per line to enforce capacity constraints.

### Consequential Actions & Human-in-the-Loop
- `purchase_requests`: Simulated procurement orders generated by the agent with idempotency keys.
- `production_change_requests`: Proposed schedule shifts for production batches.
- `customer_communications`: Simulated outbound notification drafts.
- `order_cancellations`: Formal cancellation records with audit reasons.
- `approval_requests`: Human-in-the-loop approval records with risk levels, financial values, Jev probabilistic scores, and policy citations.
- `approval_events`: Immutable logs of approval decisions (Approved/Rejected) with reviewer ID and timestamp.

### Tracing & Audit
- `agent_runs`: Top-level agent session runs with goal, plan, status, and duration.
- `agent_steps`: Granular operational steps executed during the run.
- `agent_tool_calls`: Audit of every typed tool executed with exact input arguments and structured output.
- `audit_events`: Immutable operational event trail.
- `user_memory`: Explicit business preferences stored per user.
